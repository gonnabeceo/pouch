# Hyperliquid — как считается итог

Источник — публичный `POST https://api.hyperliquid.xyz/info`, без ключа. Лимит — 1200 единиц веса в минуту на IP. `clearinghouseState`, `spotClearinghouseState` и `allMids` весят по 2, остальные запросы — по 20. Один аккаунт стоит около 100 единиц веса, мастер с четырьмя суб-аккаунтами — около 560, обновление занимает ~35 секунд.

## Режимы аккаунта решают, что складывать

`userAbstraction` возвращает режим аккаунта. Суммы проверены на живых адресах сверкой с запросом `portfolio` — итогом, который показывает интерфейс Hyperliquid.

| Режим | Что в итоге | Почему |
| --- | --- | --- |
| `unifiedAccount`, `portfolioMargin` | спот + vaults + стейкинг HYPE | Все балансы и нереализованный PnL живут в спот-состоянии. Account value перпов здесь равен лишь выделенной марже плюс доступному к выводу (маржа + доступное к выводу); если прибавить его, итог задвоится. На аккаунте с isolated-позицией итог интерфейса в точности равен спот-балансу USDC. |
| `disabled`, `default`, `dexAbstraction` (стандартный) | account value по всем перп-биржам + спот + vaults + стейкинг | Перпы и спот раздельны, у каждой перп-биржи (основной и HIP-3) свой баланс. На момент проверки бирж было 11; сумма account value по ним совпала с перп-итогом интерфейса с точностью до движения цен. |

Номинал позиций в сумму не входит никогда: нереализованный PnL уже внутри account value или спот-баланса.

## Сверка на живых аккаунтах

Правило проверено на семи реальных аккаунтах разных типов: стандартный мастер с vault и четырьмя
суб-аккаунтами в unified-режиме (с позициями и без), unified с vault и стейкингом HYPE, unified
с дюжиной открытых позиций. Итог Pouch по каждому аккаунту совпал с итогом интерфейса Hyperliquid
в пределах 0,1% — это разница во времени между запросами при движении цен. Тестовые записи этих
ответов в `backend/tests/fixtures/hl_*.json` обезличены: адреса заменены, суммы масштабированы.

Если расхождение по аккаунту больше 1% (и больше $1), у кошелька появляется предупреждение.

## Стейкинг не дублирует спот

`delegatorSummary` даёт делегированное, не делегированное (на стейкинг-счёте) и ожидающее вывода. Проверено на аккаунте, где HYPE есть и на споте, и в стейке: итог интерфейса сходится, только если сложить и то и другое, а без стейка расхождение больше 20%. Значит, это разные деньги.

## Суб-аккаунты и HyperEVM

- Добавляется только мастер-адрес. `subAccounts` возвращает суб-аккаунты, у каждого свой режим, спот, перпы на всех биржах, vaults и стейкинг. В интерфейсе они показываются вложенно.
- Балансы в сети HyperEVM — это EVM: чтобы их учесть, добавьте тот же адрес как EVM-кошелёк, Zerion поддерживает HyperEVM.
